# NeonTag 使用指南

黑 / 灰 / 荧光绿图片标注工具，支持日间主题。原生 HTML 页面，Python 后端，本地 Qwen VL 推理。

## Linux 启动

建议 Python 3.11 或 3.12（支持 3.10–3.13），NVIDIA GPU 和兼容 PyTorch 的驱动。把整个 `NeonTag` 文件夹上传服务器：

```bash
cd NeonTag
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
python main.py
```

服务监听 `0.0.0.0:8080`。浏览器打开 `http://服务器IP:8080`，并放通服务器的 8080 端口。路径指服务器文件系统上的目录。绑定地址 `0.0.0.0` 不作为远程浏览器目标地址。

检查 GPU：

```bash
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

若 `torch.cuda.is_available()` 为 False，检查驱动及 PyTorch CUDA 构建，按 [PyTorch 安装选择器](https://pytorch.org/get-started/locally/) 安装适配版本。支持 CPU 回退，但很慢且需要足够内存。4B 权重半精度约 8GB、8B 约 16GB，运行时还需要额外空间；可用显存不足会尝试自动分配至 CPU，实际内存需求随图片尺寸及生成长度变化。本项目不强制安装 FlashAttention。

## 模型

下拉选项：Qwen3-VL-4B-Instruct（默认）和 Qwen3-VL-8B-Instruct。切换选择后自动检查，缺失自动下载；默认初始选项可点击「检查 / 下载」开始。下载日志在页面可展开，失败可重试；推理在首次任务时加载。

下载目录固定在项目内部，等价命令为：

```bash
modelscope download --model Qwen/Qwen3-VL-4B-Instruct --local_dir ./models/Qwen3-VL-4B-Instruct
modelscope download --model Qwen/Qwen3-VL-8B-Instruct --local_dir ./models/Qwen3-VL-8B-Instruct
```

不需要同时下载两个模型。下载前预留足够磁盘容量；模型完整性检测检查配置、处理器、词表及索引中的全部权重文件是否存在且非空，首次加载由 Transformers 验证文件内容。

已有模型时选择「本地 Qwen VL 模型」，输入服务器上的模型目录并点击「检查本地模型」。支持 Qwen2-VL、Qwen2.5-VL、Qwen3-VL 的标准 BF16/FP16 safetensors 权重；暂不支持 AWQ、GPTQ、GGUF 等预量化权重。目录需包含配置、处理器、词表和完整权重。本地模型直接读取原目录，检查成功后路径转为绝对路径；任务记录固定该路径，继续时使用原模型。

## 工作台

页面固定在当前窗口内，任务列表占据主要区域；长任务列表、设置和日志仅在各自区域内滚动。左侧设置分为基本设置、标签规则、图像处理，可整体收起。随机测试默认折叠，抽图预览使用弹窗。提示词可展开编辑，日志支持跟随、放大及折叠。右上角切换日间 / 夜间主题，浏览器记住选择。

点击任务展开缩略图，点击任意图片打开左右审核弹窗：左侧图片、右侧标签。标注过程中可查看待处理、生成中、完成和失败项，标签生成后自动更新；暂停或完成后可编辑保存。实时日志每秒更新，记录标注、重试、错误、暂停、取消、恢复及导出，最近 500 条保存在项目 `.state/jobs`，不写入输出目录。

## 使用

1. 选择模型并下载，输入图片文件夹，点击读取。默认当前层全部图片，支持 JPG/JPEG、PNG、WEBP、BMP、TIF/TIFF。可取消部分图片的选择。
2. 可选「缩放并统一重命名」：处理该目录全部图片，按长边等比例缩放（含放大小图），默认 1024；前缀、JPG/PNG/WEBP 可改。先显示确认，原图备份在 `.state/backups/<操作ID>`，转换全部成功后再替换原图，普通运行错误会回滚；不覆盖非图片文件。转换中不要强制终止服务，异常断电后可从备份还原。
3. 设置新的空输出目录、TXT/JSON/CSV、合放或分开存放。默认合放；分开放在 `images` / `labels`。保留源图片格式及文件名，同名不同扩展名会提示先重命名。输出目录不能与输入目录或项目内部目录重叠，不覆盖其他任务数据。
4. 编辑提示词、最少标签数量、触发词。默认 20 个不重复的英文视觉标签；数量指逗号分隔的标签短语，而非英文空格单词数。触发词前置，使用英文逗号分隔，不计入最少数量。不足数量会重试最多 3 次，仍不足记失败，不自动虚构标签。
5. 「抽取预览」默认随机两张（可设置 1–50），从当前选中图片抽取。确认图片后点击开始测试；审核窗口可编辑并保存标签。修改设置后重新抽取测试。测试任务单独存储在 `.state/tests/<任务ID>`，不写正式输出目录。
6. 确认测试效果后，开始批量。支持暂停、取消、继续 / 重试；取消保留已生成数据。继续使用该任务建立时的模型、提示词和路径，修改设置用于新任务。调整设置后重新标注请使用新空输出目录。
7. 页面刷新后从任务记录选择；服务重启后运行中任务变为暂停，可继续。成功数据通过 SHA-256 校验后跳过，丢失或被外部修改的结果会重新生成；通过审核窗口保存的修改可正常保留。源图片发生变化会记失败，应使用新任务。未完成任务的源目录不能再缩放重命名。
8. 完成或暂停后可打包已成功数据。压缩包名称可输入，默认 ZIP，支持 TAR.GZ；RAR 依赖系统 `rar`，Ubuntu 可用 `sudo apt-get install rar`（需要对应软件源）。压缩包放在输出目录的父目录，内部保留输出目录名；已有同名包会拒绝覆盖。页面显示压缩包图标、名称、大小及带图标的下载按钮，点击下载到浏览器所在电脑。刷新或重启服务后选择对应任务可继续下载。测试任务的压缩包也位于测试输出目录同级。

输出目录仅包含图片和标签，分开模式只有两个对应子目录。标签与图像文件同名，TXT 为一行逗号标签，JSON 为 `{"tags":[...]}`，CSV 为单列 `tags`。任务记录、测试数据、备份、批量处理临时文件在 `.state` 内。人工修改标签时，在输出目录的父目录创建短暂的 `.neontag-*.tmp` 文件，完整写入后原子替换正式标签并清理；不进入输出目录，可兼容项目与输出位于不同磁盘。强制断电遗留的同级临时文件可删除。任务仅逐张处理，一个进程只能执行一个推理任务。暂停 / 取消会在生成 token 时请求停止，模型下载、加载和磁盘操作需等待当前操作结束。

部署在可信网络，或通过服务器端口转发访问。该工具可操作服务器路径，不含公开互联网登录功能。不要同时启动多个进程写入同一项目的任务目录。

## 项目结构

```text
NeonTag/
  main.py
  requirements.txt
  models/
  neontag/
    files.py
    models.py
    jobs.py
    web.py
  templates/index.html
  static/app.js
  static/style.css
  tests/
  .state/                    运行后自动生成
```

## 验证

```bash
python -m unittest discover -s tests -v
```

文件处理和 Flask 测试只需 Flask、Pillow；真实模型推理需要完整依赖和模型权重。测试使用可控推理替身验证任务状态和真实文件输出，不代表 GPU 标注质量验证。
